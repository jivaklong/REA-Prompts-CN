# REA 调查提示词集（REAP）—— 与代码智能体协同逆向工程

一套为【REA（Reverse Engineer Anything，万物逆向工具）】精心整理的提示词。依托这套工具链，你可以让AI代码智能体探查软件底层原理，支持原生二进制程序、固件、内核、游戏、Electron应用、APK以及网站。

提示词可直接复制给智能体使用。将所有<尖括号内>的内容替换为你的信息，每次仅聚焦一个功能点——问题越精准，输出结论越详实、证据越充分。

## 4. 软件与功能复刻

> 
> 净室复刻原则：只提取**行为逻辑**，不复制代码。严禁直接复制私有源码、资源素材、品牌标识、授权校验逻辑。

### 完整应用行为复刻方案

```
把 <应用> 当成黑盒，用 REA 做净室复刻调研。
输出 CLONE_SPEC.md 文档，包含：所有用户可见功能、页面、状态机；输入输出与边界场景；用到的文件格式和网络协议；配置与持久化存储；异常处理逻辑。

```

### 单独复刻一个功能到我的项目

```
用 REA 还原 <应用> 中 <功能> 的精确行为：触发条件、输入参数、处理步骤、输出结果、副作用、异常分支。
然后用 <我的开发语言/项目> 从零实现这个功能，保证行为对齐，并基于逆向得到的规则编写测试用例。

```

### 复刻版本和原版一致性校验

```
对比 <我的实现> 和 <原版应用> 的观测行为。

```

### 复刻交互逻辑（不使用原版素材）

```
用 REA 分析 <应用>，梳理交互模型：布局逻辑、快捷键、命令分发、撤销/重做机制、剪贴板格式。
在 <我的框架> 里复刻这套交互逻辑，素材全部使用我自己的，保证语义一致。
每一条规则都标注原版对应的函数作为证据。
```

## 6. 游戏移植到 WASM

### 原生游戏浏览器 WASM 移植评估

```
用 REA 分析 <游戏程序/源码>，评估移植到 WASM 的可行性。
梳理：主循环与帧率控制、渲染后端（OpenGL/DirectX/SDL/Vulkan 调用）、文件读写与存档路径、线程模型、音频输出、输入处理，以及平台专属 API、内联汇编。
对每一项标注：可直接移植 / 需要封装兼容层 / 必须重写。
附上调用函数与调用点作为证据。
```

### 输出移植方案

```
基于 REA 对 <游戏> 的分析结果，输出 WASM 移植方案：
- 工具链选型（Emscripten 或者手动编译）和所需兼容层（GL→WebGL、SDL→SDL2 兼容、pthreads→SharedArrayBuffer 线程）；
- 需要编译的最小源码模块集合；
- 存档迁移到 IndexedDB、资源走拉取/流式加载的方案；
- 原生代码里发现的性能风险（每帧频繁分配内存、忙等待循环、64位强依赖），附带对应函数证据；
- 里程碑规划，最终产出可运行的 index.html。
```

### 先移植纯逻辑内核（无头模式）

```
用 REA 把 <游戏> 的纯模拟逻辑（物理、AI、规则）和渲染、系统调用拆分开。
带证据提取精确规则，然后用 C/Rust 实现这个核心逻辑并编译为 WASM，配套测试框架，回放录制输入，对比状态哈希，验证和原版行为一致。
```

## 9. 内核分析

```

## 10. 漏洞研究

### 信任边界审计

```
使用 REA 审计 <授权范围内的应用或二进制程序> 的安全性。
优先审计信任边界、不可信输入、高权限操作、凭据存储、IPC、文件处理、命令执行。
每一条潜在漏洞，都包含：
- 输入来源与敏感操作；
- 代码路径与现有校验逻辑；
- 触发前提和影响；
- 证据与不确定点；
- 可控验证方案。
没有充分证据时，不能把假设定性为确认漏洞。
```

### 从不可信输入追踪危险函数

```
用 REA 分析 <二进制文件>。列出所有外部数据入口（网络套接字、文件、IPC、命令行、剪贴板、URL 处理器），沿着每条输入流向危险 sink 点：长度未校验的 memcpy/strcpy、system/exec、动态加载、反序列化、路径拼接。
对每一条【数据源→危险函数】链路，给出带地址的调用链，说明中间存在哪些校验。
```

### 补丁对比（寻找修复不完整的漏洞）

```
用 REA 对比 <漏洞版本> 和 <修复版本> 的 <组件>。
比对安全相关函数：新增了什么校验、二进制里其他位置有没有相同模式但没打上补丁的代码、这个修复是否覆盖了该危险函数所有调用方。
给出疑似修复不全的位置和函数地址，在可控环境验证前，统一标记为猜想。
```

### 崩溃溯源定位根因

```
用 REA 分析 <应用> 的这次崩溃。
可用材料：
<堆栈、日志、转储文件、复现步骤>
把报错和相关函数关联，提出假设，标注支撑每个猜想的证据。
设计最简实验，用来区分各个猜想、确认真实根因。
```

### 数据流向审计

```
我已获得授权分析 <程序>。用 REA 找到它存储、发送 <这类数据> 的位置。
给出代码路径，说明数据在本地存储和传输时是否加密，列出具体风险并附上证据。
```

## 12. 反作弊与保护机制研究

> 
> 仅限：你自己的机器、自研软件、厂商漏洞赏金项目、CTF、学术研究。**禁止在其他玩家的正式游戏环境中使用**。

### 梳理反作弊的检测面

```

## 提示词编写技巧（为什么这套提示词好用）

1. **一个提示词只盯一个功能**。宽泛的“解释整个软件”只能得到粗浅概览；问题越窄，越能拿到调用链和地址。
2. **强制要求证据**。这套所有提示词都要求标注文件/函数/地址，避免 AI 凭空编造。
3. **事实 / 推论 / 未知 三分类**，防止猜想被当成定论。
4. **优先静态分析**。在确实需要运行观测之前，加上“不要执行程序”。
5. **明确交付物**：SPEC 文档、读取脚本、移植方案、最小复现代码。固定产出会倒逼智能体自证结论。
6. **提前声明范围**：“自有实验机”、“仅限离线单机”、“只做文档、不绕过校验”，保证结果适合安全调研与报告输出。
